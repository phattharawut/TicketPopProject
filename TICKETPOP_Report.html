System Overview

TICKETPOP คือแอปพลิเคชัน Android สำหรับจองตั๋วคอนเสิร์ต รองรับผู้ใช้ 2 ประเภทคือ Customer (ผู้ซื้อตั๋ว) และ Admin (ผู้จัดการระบบ) ระบบแบ่งออกเป็น 2 ส่วนหลัก ได้แก่

Frontend: Android app เขียนด้วย Kotlin + Jetpack Compose ใช้ Retrofit2 สำหรับ HTTP requests, ZXing สำหรับ QR Code, Coil สำหรับโหลดรูปภาพ
Backend: Node.js + Express.js API server เชื่อมต่อกับ MySQL/MariaDB ผ่าน mysql2 library, ใช้ JWT สำหรับ Authentication, bcryptjs สำหรับ hash รหัสผ่าน, multer สำหรับ upload รูปภาพ

🔗 ความสัมพันธ์ระหว่างตาราง (Relationships)

users 1 ──────── N bookings — ผู้ใช้หนึ่งคนมีได้หลาย Booking (ON DELETE CASCADE)
concerts 1 ──────── N zones — คอนเสิร์ตหนึ่งมีได้หลายโซน (ON DELETE CASCADE)
zones 1 ──────── N seats — โซนหนึ่งมีได้หลายที่นั่ง (ON DELETE CASCADE)
concerts 1 ──────── N seats — seats เก็บ concert_id เพื่อ query ตามคอนเสิร์ตได้ตรง
bookings 1 ──────── N tickets — Booking หนึ่งมีได้หลาย Ticket (ON DELETE CASCADE)
zones 1 ──────── N tickets — Ticket อยู่ในโซนใดโซนหนึ่ง
seats 1 ──────── 1 tickets — Ticket นั่งระบุ seat_id (NULL สำหรับ Standing)

หมายเหตุ concert.status

Upcoming — ประกาศแล้วยังไม่เปิดขาย  |  OnSale — เปิดขายปกติ  |  SoldOut — ตั๋วหมด  |  Ended — คอนเสิร์ตจบแล้วตามปกติ  |  Cancelled — Admin ลบคอนเสิร์ต (Soft Delete) → ตั๋วของ user แสดงสีแดง "ยกเลิก"

🎵 Concerts
MethodEndpointDescriptionBody / ParamsResponse data
GET /api/concerts รายการคอนเสิร์ต (ซ่อน Ended/Cancelled) — Concert[] + minPrice
GET /api/concerts/:id รายละเอียดคอนเสิร์ต concertId (path) Concert object
POST /api/concerts Admin สร้างคอนเสิร์ต + zones + seats title, venueName, showDate, showTime, posterImageUrl, zones[] { concertId }
PUT /api/concerts/reorder Admin เรียงลำดับคอนเสิร์ต (ต้องอยู่ก่อน /:id) orders[] → { concertId, sortOrder } —
PUT /api/concerts/:id Admin แก้ไขคอนเสิร์ต title, description, venueName, showDate, showTime, posterImageUrl, status —
DELETE /api/concerts/:id Admin ลบคอนเสิร์ต (Soft Delete → status='Cancelled') concertId (path) —
📍 Zones & Seats
MethodEndpointDescriptionBody / ParamsResponse data
GET /api/zones/:concertId ดึงโซนทั้งหมด + remainingSeats concertId (path) Zone[] (capacity = remaining สำหรับ Seated)
GET /api/concerts/:id/zones-seats ดึงโซน + seats ทั้งหมด (Admin layout) concertId (path) Zone[] + seats nested
GET /api/seats/:zoneId ดึง seats ของโซน (auto-generate ถ้าว่าง) zoneId (path) Seat[]
PUT /api/seats/:seatId/toggle Admin toggle is_active ของที่นั่ง seatId (path) { isActive }
🎫 Bookings & Tickets
MethodEndpointDescriptionBody / ParamsResponse data
POST /api/bookings จองตั๋ว (Transaction + lock seats) userId, zoneId, seatIds[], standingCount, totalAmount, paymentMethod { bookingId, status }
GET /api/users/:userId/tickets ดึงตั๋วทั้งหมดของ user (พร้อม concertStatus) userId (path) Ticket[]
GET /api/tickets/:ticketId ดึงตั๋วตาม ID (สำหรับ QR Screen + Admin scan) ticketId (path) TicketDetail + holderName + isUsed
PUT /api/tickets/:ticketId/use Mark ตั๋วว่าใช้แล้ว (Admin check-in) ticketId (path) —

Soft Delete System

เมื่อ Admin กด "ลบคอนเสิร์ต" ระบบจะ ไม่ลบข้อมูลจริง แต่เปลี่ยน concerts.status = 'Cancelled' ทำให้ concert ไม่แสดงในหน้า Home แต่ตั๋วของ user ยังอยู่ในระบบ โดยแสดงสถานะ ยกเลิก (สีแดง)

Concert Status Lifecycle

Statusความหมายแสดงใน Homeตั๋วแสดงเป็น
Upcomingประกาศแล้ว ยังไม่เปิดขาย✅ แสดงปกติ
OnSaleเปิดจำหน่ายตั๋ว✅ แสดงปกติ (กดดู QR ได้)
SoldOutตั๋วจำหน่ายหมดแล้ว✅ แสดงปกติ
Endedคอนเสิร์ตจบตามปกติ❌ ซ่อนจบไปแล้ว (สีเทา)
CancelledAdmin ลบ (Soft Delete)❌ ซ่อนคอนเสิร์ตถูกยกเลิก (สีแดง)

Seat Management

Auto-generate seats: เมื่อสร้างโซนประเภท Seated ระบบจะ auto-generate seats ตาม capacity โดยใช้ A-Z เป็น row label และ 1-N เป็น number label (seatsPerRow = 5 by default)

Toggle seat: Admin สามารถ toggle is_active ของแต่ละ seat ผ่าน AdminSeatLayoutScreen เพื่อปิด/เปิดที่นั่งชั่วคราว

Reserve on booking: เมื่อ user จอง is_reserved = 1 จะถูก set ทันที (ใช้ MySQL Transaction + FOR UPDATE lock เพื่อป้องกัน race condition)

QR Code Format

QR Content: TICKETPOP|{bookingId}|{ticketId}|{zoneName}
ตัวอย่าง: TICKETPOP|22|32|Standing Floor
Admin scan → verify ด้วย GET /api/tickets/:ticketId → check-in ด้วย PUT /api/tickets/:ticketId/use

Architecture Pattern

🎨
UI Layer (Composables)
Screens รับ ViewModel และ NavController, observe StateFlow/State ด้วย collectAsState()
🧠
ViewModel Layer
AndroidViewModel จัดการ state (MutableStateFlow / mutableStateOf), เรียก Repository ผ่าน viewModelScope.launch
🗄️
Repository Layer
เรียก API ผ่าน Retrofit interface, unwrap ApiResponse, throw Exception เมื่อ success=false
🌐
API Client (Retrofit)
ApiClient singleton สร้าง Retrofit instance พร้อม GsonConverterFactory และ AuthInterceptor เพิ่ม JWT header
